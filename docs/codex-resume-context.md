## 项目关系

- **KK（`g_kube_installer`）**：基于 Go 的安装工具，围绕 Kubernetes、组件、离线资源及主机部署组织安装流程。
- **Web 安装器（`g_web_installer`）**：提供安装、备份恢复和离线资源管理等操作入口，与 KK 等组件配合完成交付。
- **私有化服务（`private-service`）**：围绕产品、部门、交付版本和对象存储资源提供业务服务。

以上是简历讨论的工作划分，具体系统边界和实际职责需由本人确认。

## KK：安装与离线交付

### 轻量化离线安装链路

- 业务背景：部分场景希望在主机上运行 Docker Compose 应用，不依赖 Kubernetes，并支持离线资源交付。
- 可展开的工程内容：主机环境预检、Docker Engine 与 Compose 准备、Zot 镜像仓库、离线包生成和业务镜像导入；隔离轻量化流程与原有集群安装流程。
- 源码线索：`cmd/kk/pkg/pipelines/install_docker_compose.go`、`cmd/kk/pkg/images/tiny_push.go`。检查相关功能分支和版本后再使用。
- 证据边界：历史记录有代码和最小离线包结构验证；干净主机的完整安装及镜像推送未验证。不能写成已完成生产上线或完整端到端验证。
- 候选表述：参与轻量化离线部署链路建设，梳理主机预检、运行环境准备和离线镜像导入流程，支持非 Kubernetes 的交付场景。

### 组件安装与问题治理

- 可展开的工程内容：基于模块化安装任务组织组件资源准备、镜像同步和 Helm 安装；排查 PostgreSQL 扩展检查中嵌套 shell 与 JSONPath 的引用问题。
- 源码线索：`cmd/kk/pkg/component/tasks.go` 及对应组件的实际嵌入式 Helm 包。
- 证据边界：历史问题修复存在构建或启动记录；是否完成目标环境的业务功能验证，应针对具体版本重新核实。
- 候选表述：参与组件安装流程和部署问题治理，围绕离线资源、Helm 包及安装前检查分析兼容性问题。

## Web 安装器：资源管理与数据运维

### 对象存储资源与离线版本导入

- 业务背景：私有化交付需要管理离线版本、镜像包和数据库包，并能追踪后台导入过程。
- 可展开的工程内容：围绕对象存储元数据管理文件与版本资源；同一后台任务串行处理多个资源，记录普通镜像失败并继续处理，关键错误终止；利用任务日志追踪进度与结果。
- 源码线索：`internal/service/file_server/file_server_v3.go`、`internal/service/file_server/obs_v3_version_import.go`。
- 证据边界：源码和历史测试支持对流程的分析；具体版本在真实现场的失败后继续行为需要另行验证。进程内互斥不能表述为分布式锁，也不能称为数据库与对象存储之间的事务。
- 候选表述：参与离线版本导入和资源管理能力建设，梳理多资源串行处理、失败记录与任务状态追踪。

### 数据库结构同步

- 业务背景：升级或数据迁移时，需要先核对数据库结构变更，再有控制地应用。
- 可展开的工程内容：将 MariaDB 结构同步分为准备和应用阶段，先生成可审阅的变更 SQL，再执行应用；结合备份与状态标记考虑恢复边界。
- 源码线索：`internal/service/importdata/mariadb_schema_sync.go`。
- 证据边界：历史记录包含真实 API 测试；具体测试结果及对应提交需在写简历前复核，不能直接推导为所有客户环境均已验证。
- 候选表述：参与数据库结构同步流程优化，通过准备和应用分阶段处理，使变更具备审阅环节。

## 私有化服务：交付版本与对象存储

### 产品、部门和交付版本关联

- 业务背景：按产品部门组织交付版本和相关对象存储目录，为版本输出及文件上传提供路径和业务关联。
- 可展开的工程内容：梳理部门创建、版本输出、目录创建以及对象上传的调用链和路径契约。
- 源码线索：`internal/app/service/privatization/service.go`、`internal/app/repository/privatization/repository.go`、`internal/app/pkg/util/obs.go`。
- 证据边界：历史记录有代码交付信息；目标现场部署和真实对象存储验证不能仅根据代码推断。
- 候选表述：参与私有化交付版本与对象存储目录的集成，梳理部门、版本与文件路径之间的关联。

### 对象存储资源模型与迁移方案

- 可展开的工程内容：围绕目录和文件层级、部门版本、对象键、包类型及审批信息整理资源模型；盘点历史对象，设计初始化 SQL 与逐条迁移命令，并核对源目标路径。
- 源码线索：`internal/app/model/entity/obs.go`、`ops_install/template/sql/schema.sql`。检查对应工作区和分支；相关内容在本次检查时包含未提交改动。
- 证据边界：历史 SQL 和对象迁移命令属于准备或核对材料，不能写成已执行；资源模型不等于完整业务读写集成。数据库事务无法回滚对象存储操作，实际迁移还需考虑幂等、重试和对账。
- 候选表述：参与对象存储资源模型和历史资源迁移方案梳理，关注路径一致性及跨系统操作的恢复边界。
