# RAG Code Walkthrough

## 工作流

1. 先读取当前作用域内的 `AGENTS.md` 并遵守其学习、笔记、验证和安全规则。讲解 `3_rag_from_scratch` 前，按仓库规则读取 `docs/learning-handoff.md`，从当前学习进度继续。
2. 将讲解任务默认视为不修改业务代码的任务。除按 `AGENTS.md` 应维护的学习笔记外，未经用户明确要求不改业务代码、不顺手修复问题，也不扩大到提交或推送。
3. 从用户点名的文件、函数或问题出发，定位真实入口：检查 `main()`、`if __name__ == "__main__"`、CLI 参数解析、导入关系、调用方和被调用方。区分可运行入口、仅编译文件、辅助模块和替代入口。
4. 从源码、现有启动注释和参数解析代码确认启动命令及参数枚举。不要根据文件名猜命令；存在多条运行路径时，说明本次跟踪哪一条以及其他路径的差异。
5. 按程序实际发生的顺序追踪调用链，包括关键分支、配置来源、框架调用和返回路径。优先引用项目源码；框架行为无法从项目源码确定时，再检查当前安装版本的源码或官方文档。
6. 对每个关键步骤展示：
   - 当前执行的表达式或函数。
   - 代表性的输入值及其 Python 类型。
   - 返回值或副作用及其 Python 类型。
   - 下一步由谁消费该结果。
7. 优先用安全、低成本的本地运行结果验证中间值。无法实际运行时，明确标记为“根据源码推导”或“示例值”，不得把推导值描述成实测值；不得为了讲解调用付费接口、修改外部系统或暴露 `.env`、API Key、Token。

## LangGraph 专项说明

遇到 LangGraph 时，按一次节点执行拆成以下阶段，不把它们混成一个结果：

1. 节点执行前的完整 State。
2. 节点实际收到的输入，以及临时拼给模型但未写入 State 的输入。
3. 节点返回的 partial update，例如 `{"messages": [response]}`。
4. 对应字段使用的 Reducer，以及 Reducer 如何合并旧值和新值。
5. 合并完成后的新 State，以及路由或下一个节点实际读取的内容。

同时给出普通 Python 等价写法，例如用 `dict` 复制、字段赋值和列表拼接模拟节点更新与 Reducer 合并。若字段没有 Reducer，明确说明它是覆盖而不是追加。

## 输出要求

- 先给当前代码路径的结论，再展开执行顺序。
- 使用 `相对路径:行号` 引用真实文件；回答前重新确认当前行号。
- 解释具体对象时，优先展示可读的 Python 表示、字典或 JSON，并标明精确类型。
- 明确区分项目自定义逻辑、Python 语法、LangChain 行为和 LangGraph 行为。
- 给出足以理解当前代码的普通 Python 等价写法，不另造一套与当前路径无关的大型示例。
- 若运行条件、依赖或外部服务使结论不能验证，直接说明证据边界和未验证部分。

## 学习笔记

按 `AGENTS.md` 维护笔记，并在写入前搜索现有内容，避免重复：

- 仅把新学到的 Python 基础语法写入 `Python基础语法笔记.md`，不要把所有 Python 相关内容都归入基础语法。
- 把新学到的 LangChain 语法或框架行为写入 `LangChain基础语法笔记.md`。
- 把新学到的 LangGraph 语法、State、Reducer 或路由行为写入 `LangGraph基础语法笔记.md`。
- 没有新增可复用知识时不为凑记录而修改笔记；不要把业务逻辑复制进语法笔记。

## 边界

- 单纯要求修复 bug、实现功能或重构时不要自动使用本 Skill。
- 用户在修复任务中显式调用本 Skill 时，只对其要求的代码路径提供上述讲解，不据此扩大修改范围。
- 不把 README、注释或记忆中的旧结论当作当前运行事实；与源码不一致时以当前源码和可复现运行结果为准。
