# REL-03：改manifest后旧artifact和镜像缓存不会自动变化

项目：g_kube_installer / g_web_installer。记录状态：代码已验证。来源会话起始日期：2026-09-20, 2026-10-09（含之后续问，不是本次现场检查日期）。

适用标签：Kubernetes any；系统 any；安装模式 offline。any 表示历史证据未限定，需按实际版本再次核对；不是承诺所有环境兼容。

## REL-03 问题与表现

清单已减少镜像/补Zot，但上传的artifact仍旧，缺pause3.10。

## REL-03 最终根因或已确认边界

manifest、工作缓存、最终tar与已推仓库是四个不同对象。缓存复用要求镜像身份/摘要正确，旧镜像可能留在缓存。

## REL-03 处理方案

先停旧export，按新manifest保留有效缓存、精确清淘汰项，再重导出检查成员并补推。不能整目录清空正在下载的镜像，也不能只复制manifest就宣布制品更新；镜像tag/架构必须覆盖目标节点。

## REL-03 验证证据与限制

历史84→62清单切换/22旧缓存清理已执行；清理与完整artifact完成不是同一证据。
