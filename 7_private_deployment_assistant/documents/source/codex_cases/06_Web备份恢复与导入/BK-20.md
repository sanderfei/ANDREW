# BK-20：MySQL导入不能复用为PostgreSQL/pgvector导入

项目：g_web_installer。记录状态：历史功能验证。来源会话起始日期：2026-08-20（含之后续问，不是本次现场检查日期）。

适用标签：Kubernetes any；系统 any；安装模式 any。any 表示历史证据未限定，需按实际版本再次核对；不是承诺所有环境兼容。

## BK-20 问题与表现

请求只增加postgresql枚举，却仍走mysql_data.zip/mysql客户端。

## BK-20 最终根因或已确认边界

PostgreSQL协议、dump、事务/角色/extension与MySQL不同；pgvector是PostgreSQL扩展。

## BK-20 处理方案

独立postgresql_data.zip分支，验证根目录dump/backup/sql文件名与PGDMP头，custom用pg_restore、SQL用psql及相应事务/退出错误策略。每库启用/检查vector并避免owner/privilege不匹配。服务端需PG客户端，凭据不进入脚本或参数。

## BK-20 验证证据与限制

后续历史HTTP多库ZIP含custom/plainSQL，vector3、HNSW与最近邻及索引使用验证通过。

以上为历史归档结论，本次仅整理文档，未重新连接客户环境、部署或触发业务操作。
