# BK-28：prepare漏过滤版本注释DROP导致误删原业务库

项目：g_web_installer。记录状态：历史功能验证。来源会话起始日期：2026-08-20（含之后续问，不是本次现场检查日期）。

适用标签：Kubernetes any；系统 any；安装模式 any。any 表示历史证据未限定，需按实际版本再次核对；不是承诺所有环境兼容。

## BK-28 问题与表现

prepare处理Nacos SQL失败，A库被版本注释形式DROP DATABASE误删。

## BK-28 最终根因或已确认边界

旧保护只识别普通DROP，漏MySQL/*!...*/与MariaDB/*M!...*/；暂存导入在同实例不能自动保证原库隔离。

## BK-28 处理方案

历史从prepare前全量备份恢复A，再过滤普通和版本注释DROP DATABASE/SCHEMA，将CREATE/ALTER DATABASE和USE重写到临时库，导入前再验证只指向暂存上下文。拒绝异常而非mysql--force继续。完全限定table引用风险另见BK-23，不能宣称任意SQL都安全。

## BK-28 验证证据与限制

564f4eb，现场A恢复6库/临时库0；修复后最终完整闭环通过。
