## BK-37 已确认原因与边界

1. `com.google.common.collect.Iterables` 属于 Google Guava。客户当前 APOC 导出执行路径无法加载这个类，说明其运行依赖不可见；过程已经注册不代表运行时依赖齐全。
2. 直接读取 APOC 官方 5.26.11 tag 的 `core/build.gradle:55-61`，Guava 33.0.0-jre 被声明为 compileOnly，该段说明这类依赖不会打包进 Core JAR，需要由数据库或额外 JAR 提供。因此镜像和 APOC 的版本号相符，也不能单独证明运行依赖完整。
3. 后续已取得客户镜像归档并在214复现同一个错误，确认该镜像结合客户插件加载方式会触发依赖不可见。仍未取得客户运行Pod全部JAR及类路径，不能将根因进一步写成某个指定guava.jar文件损坏或必须补某个具体版本。镜像内容、实际挂载和插件类路径仍需区分。
4. 当前手动调用已绕过 Web 脚本而在数据库内部失败，至少有一个 Neo4j 插件运行时阻断项需要修复。不能把它仅归因为 Web 未更新，也不能凭此声明 Web 其他执行及归档环节没有问题。
5. 原配置持久化、注册与 exec 调用阶段记录见 [BK-35](BK-35.md)，历史凭据不一致见 [BK-36](BK-36.md)。本案例独立记录实际 Guava 类加载错误，避免与此前标签、配置或认证根因合并。
