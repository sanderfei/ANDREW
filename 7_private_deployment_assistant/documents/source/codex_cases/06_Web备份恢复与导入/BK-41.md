# BK-41：Neo4j 备份时 APOC 导出过程未注册

项目：g_web_installer。记录日期：2026-11-02。状态：用户回传的 Helm、挂载及配置查询结果与 9 月 29 日 APOC 配置未应用高度吻合；环境变量和修复效果待核实。

## 环境与表现

用户提供 Web 备份日志截图，目标 Neo4j Pod 名为 `neo4j-0`，数据库为 `neo4j`；用户随后回传该 Pod 的镜像为 `bitnami/neo4j:5.26.28`，且 `/var/lib/neo4j/labs/apoc-5.26.28-core.jar` 文件存在。Helm 显示 release `neo4j` 的 revision 1 于 2026-09-24 安装，Chart 为 `neo4j-5.3.0`、app version 为 `5.26.28`；Pod 为 Running、0 次重启、运行 39 天。日志显示已进入该数据库导出步骤，但返回：

- 用户回传的 Helm release 安装时间早于 KK 在 2026-09-29 的 `58accf9` 中加入 APOC 配置。`neo4j-user-config` 和 `neo4j-default-config` 的插件目录、unrestricted 与 allowlist 指定字段均为空；名为 `neo4j-apoc-config` 的 ConfigMap 不存在，Pod 卷列表也没有引用该 ConfigMap。容器日志中过滤 APOC / plugin 的命令无输出，仅说明没有匹配行。
- 上述时间、配置及挂载证据高度支持现场未应用 9 月 29 日 APOC 配置，能解释过程未注册；但仍未核对容器环境变量及其他可能的配置来源，不能把环境覆盖或其他加载异常排除为已确认事实。相同 Chart 版本号也不证明其归档与新包内容一致。
- 用户在 master 上检查 `/tmp/g_kube_installer/neo4j.tgz` 时提示文件不存在；尚未对客户现场执行 Helm 升级或修复。

- 现有信息记录了升级前 PVC、PV 和挂载参数；尚未停库、复制、升级或恢复，尚未确认存在可恢复的独立快照或副本，也未验证升级后 PVC 身份和数据内容。

## PVC 备份方式纠正

此前建议停库后使用 `cp -a` 复制 PVC 并用 `diff` 比对，不能作为官方支持或已验证可恢复的数据库备份。Neo4j 的 [5.x Helm 迁移说明](https://neo4j.com/docs/upgrade-migration-guide/current/version-5/migration/standalone/helm-example/)和[备份规划](https://neo4j.com/docs/operations-manual/current/backup-restore/planning/)指出，不支持通过文件系统直接复制数据库，可能导致存储损坏；文件比对只核对文件内容，不证明数据库一致性和恢复能力。此类副本最多作为额外应急副本，不替代正式备份。

若要求可靠备份，应先确认目标版本与现场操作条件，使用适用于 Neo4j 5.26 的 `neo4j-admin database dump` 离线备份 `neo4j` 和 `system`，将备份保存到独立存储，再在隔离实例执行恢复并核验数据；配置、认证及其他所需文件的保障边界须单独核对。StatefulSet 缩容到 0 后原 Pod 不存在，不能直接在原 Pod 中执行 dump，需要另行确定可安全访问原 PVC 的离线维护方式。本次未执行 dump、隔离恢复或升级。

## 排查与处理

1. 在有目标集群访问权限的主机确认上下文，按实际命名空间查看 `neo4j-0` 的容器镜像、Chart / Helm release、配置来源和挂载，再检查实际运行插件目录中的 JAR、与 Neo4j 版本的匹配情况、插件加载相关日志和过程加载配置。只提取必要内容，不输出完整配置、Secret 或账密。
2. 在 Neo4j Cypher Shell 交互式登录后执行 `SHOW PROCEDURES YIELD name WHERE name = 'apoc.export.cypher.all' RETURN name;`。若版本不支持该查询，应使用对应版本提供的过程列表命令。
3. 根据实际 Chart 和镜像补齐兼容版本插件、加载目录及允许列表，持久化到真正的配置来源；另确认 APOC 的文件导出已启用，导出目录与 Web 读取目录一致。变更可能要求重启数据库，按业务维护窗口及工作负载更新策略执行，保留现有 PVC 和配置。不要直接用其他 Chart 的 values 或路径。
4. 过程注册后重新执行 Web 备份，查看异步任务最终日志并核验归档与 `.cypher` 内容；若要求证明可恢复，还需在隔离环境恢复验证。
