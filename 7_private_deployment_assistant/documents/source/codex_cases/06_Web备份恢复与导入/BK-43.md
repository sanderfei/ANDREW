## 机制与处理

当前 Web 源码 `internal/service/importdata/mariadb_schema_sync.go` 的 Atlas 配置跳过删除库、表和列，但不跳过删除索引；因此保留旧字段并不保证该字段上的旧索引也被保留。prepare 在临时库导入失败时停止，不生成完成标记。`d15a46d` 新版在 prepare 成功后等待独立 apply；apply 执行前记录 `apply.started`，成功后记录 `apply.done`。旧版 `38f56b5` 则在同一 prepare 任务中自动执行。实际差异仍须以生成计划为准。

1. 上传正确 SQL 包，发起 prepare 后保存 PID；HTTP 返回只代表任务启动，应通过对应 WebSocket 日志等待最终状态，下载计划并检查差异后再单独发起 apply，使用 apply 返回的 PID 查看执行终态。
2. 若错误出现在临时导入阶段，检查包内 SQL 和导入诊断，修正后重新 prepare；不要自行创建完成标记。
3. 若 `apply.started` 存在且 `apply.done` 不存在，检查最终日志和生成方案、备份以及业务库实际状态；DDL 可能已经部分生效，应依据影响和备份情况评估恢复，不要将本次单条 ALTER 的结果推广为通用保证。
4. 检查目标索引要求及现有数据是否满足唯一约束；同时审核索引删除、重建对业务的影响。结构同步不会因为跳过删列而自动保护该列的索引。
