## 问题表现

用户调用 `POST /api/v1/clusters/k8s_test/backups/targets/milvus/run`，返回：

```json
{"code":10001,"msg":"remote validation failed: Process exited with status 1","data":null}
```

错误发生在异步备份任务创建前。不能将其解读为 `milvus-backup create` 执行失败，也不能从本次响应取得备份 PID。

## 问题原因

`RunBackup` 先调用 `validateRemoteBackupTarget`。Milvus 分支要求 Running Pod 名称包含 `standalone` 和 `minio`，没有按当前分布式部署识别入口。214 上实际 Running 的组件为 coordinator、data-node、etcd、minio、proxy、query-node、streaming-node，没有 standalone。

现场按原谓词分步执行，结果为：

```text
kubectl_path_exit=0
namespace_exit=0
standalone_match_exit=1
minio_match_exit=0
```

因此实际失败项已定位到 `grep -q standalone`。命令使用 `set -e`，无匹配时返回 1；`grep -q` 不打印提示，SSH `CombinedOutput` 为空后程序回退展示 SSH 错误字符串，最终只有 `Process exited with status 1`。

## 后续脚本的兼容问题

只放宽前置校验仍不能完成当前部署的备份。源码与现场还存在以下差异：

| 项目 | 现有备份代码 | 214 现场 |
|---|---|---|
| 执行 Pod | `component=standalone` 或名称包含 standalone | 分布式组件，入口为 `milvus-proxy` |
| Milvus Service | `milvus:19530` | `milvus` Service 不存在；`milvus-proxy` 暴露 19530/9091 |
| MinIO Service 端口 | `milvus-minio:9000` | Service 端口 80，Endpoints 后端端口 9000；通过 Service 名连接需要使用其服务端口 |
| MinIO 挂载路径 | `/export` | Pod 的 data 卷挂载为 `/bitnami/minio/data` |

bucket、rootPath、etcd 连接配置、GC 暂停地址以及工具兼容性仍须按实际部署确认，不能只替换 Pod 名称。源码里的固定对象存储凭据不能当作现场有效认证信息；本轮没有查询这些凭据或执行认证测试。

1. 按用户最终范围，仅支持当前 Chart 16.0.2 / Milvus 2.6.0 分布式部署，统一校验与执行阶段的 proxy/coordinator、容器和 Service 发现。
