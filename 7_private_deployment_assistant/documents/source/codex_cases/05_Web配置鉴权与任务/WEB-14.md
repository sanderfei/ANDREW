# WEB-14：InstallAppV1 的安装与镜像推送分支及文件格式

项目：g_web_installer。记录状态：源码结论。来源会话始于 2026-05-29 和 2026-07-22，含之后续问。

适用标签：Kubernetes any；系统 any；安装模式 any。需要核对目标 Web 版本和实际上传包，不保证任意格式兼容。

## WEB-14 问题与表现

上传 OBS 下载的镜像归档时，接口提示格式不支持；认为 DockerPush 一定输出 ZIP，或认为 `.zip` 后缀自动决定是否安装应用。

## WEB-14 最终根因与处理方案

历史 `POST /api/v1/apps/:cluster/v1` 有两种业务：`registryOptions == nil` 进入普通应用安装，读取 ZIP 中的 `app_image_list.yaml`、`private_version.xlsx` 等安装信息；带有效仓库选项时进入镜像包推送。后缀检查只验证选定分支可接受的格式，不负责选模式。

OBS registry 上传与应用安装接口不是同一个包合同。历史 V2 DockerPush 生成 Docker-save 风格 TAR，后来 V3 生成 gzip 包。单纯镜像归档没有应用安装配置，不能通过改名 `.zip` 变成完整安装包。嵌套 TAR 与可直接加载的归档还需分别识别，详见 OBS-07。

调用前先确定是部署完整应用还是只推送镜像，核对仓库参数与目标版本支持的 ZIP/TAR/TGZ 内容。不要以文件后缀替代真实格式和内部目录检查，也不要把普通应用 ZIP 的 Harbor 专用处理自动推广为 Zot 兼容。

## WEB-14 验证证据与限制

历史由 handler、服务和命名函数核对上述分支。包后缀能力随接口版本变化；本条不声明所有包组合都有真实部署验证。本次只整理文档，未执行应用安装或向量入库。
